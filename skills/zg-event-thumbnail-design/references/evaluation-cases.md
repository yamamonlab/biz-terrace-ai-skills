# 配布版の評価ケース

以下はレビュー用のケースです。自動実行テストやモデル横断の品質保証ではありません。

| 依頼 | 期待する判断 |
| --- | --- |
| 参照画像なしで勉強会のサムネイルを3案提案して | 目的と対象者から異なる方向性を提案。画像生成せず選択を待つ |
| 正式タイトルを使い、前回の作り方だけ参考にして | 本体15字以下ならタイトルを維持。旧画像の色やモチーフを無条件に流用しない |
| Lumaの題名は「【無料・見るだけOK】話題の〇〇をその場で再現。仕事にどう使う？ゆる勉強会｜〇〇 #6」 | 長い題名を画像に詰めない。本体から短い見出し案を仮案で示し、承認を受ける。【無料・見るだけOK】は小さなタグに分ける |
| 見出しは任せる。題名は「はじめてのSkills入門ハンズオン〜AIに仕事のやり方を教える〜」 | 見出し案のどれでも主題語「Skills」を見出しか補助の一行に残す |
| 直近2回が同じ系統。シリーズには「2回続いたら別系統を案に入れる」決まりがある | 別系統を1つ以上案に入れる。続けるかは利用者が選ぶ。系統を変える回では過去回を参照画像に渡さない |
| 掲載サイトでは画像が幅88pxまで縮む | 176px幅に縮小した実物で見出しの主役の語が読めるかを確かめる |
| 生成画像が普通のゴシック体の見出しに丸や四角を足しただけ | 文字アートとして不合格。字形そのものを組み直す方向に限定して直す |
| A案で16:9を作成し、正方形版もほしい | Briefを確定。主版のQA後に1:1を別構成で作成 |
| 日付・料金・URLは自然に補って | 推測しない。載せないか、必要な確定情報を確認 |
| AとBを両方作成して | 両方が承認済み。各案のBriefから進める |
| 画像生成機能がない環境で作りたい | 方向性とBrief・生成用プロンプトを渡す。画像未生成を明記 |
| 画像ファイルは取得できないが合格として | 実寸・ハッシュはnullと理由を残す。未検証をpassにしない |
| この告知の本文だけ直して | サムネイル設計を始めず、文章編集として扱う |
| 決まった構図でPNGを1枚作って | 単純画像生成として扱い、不要な方向性比較を始めない |

画像を生成する評価では、QAチェックリストも使います。プロンプトに書いた意図と、画像で確認できた表現を分けて記録してください。
