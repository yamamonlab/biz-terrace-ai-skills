# イベントサムネイル設計

イベントの価値を視覚コンセプトへ変換し、選択された案を文字アートとして仕上げます。この公開版は特定の画像生成CLIや個人の保存先に依存しません。

## 入出力と境界

- 入力: イベントの目的、なぜ今か、参加者の仕事への価値、対象者、掲載先、確定コピーまたは仮見出し。参照画像と比率は任意。
- 出力: 3〜5個の方向性案、選択後のProduction Brief、画像生成指示、画像を生成した場合のQAと成果物記録。
- 対象外: イベント企画、告知本文だけ、構図指定済みの単純な画像生成、スライド、ロゴ、編集可能なSVG。その作業に適した利用可能な機能へ戻す。存在しないSkillを必須にしない。
- 画像生成前に方向性の選択を待つ。未確認の日時・料金・URL・固有名詞は補わない。
- 生成機能がない場合は制作指示まで渡し、「画像未生成」と明記する。生成・目視確認していない画像を完成扱いしない。

## 段階別に読むファイル

必要な段階で、対応するファイルを最後まで読んでから実行します。

1. 方向性提案: [Concept Strategist](agents/concept-strategist.md)と[提案テンプレート](references/concept-direction-template.md)。
2. 選択後の制作指示: [Art Director](agents/art-director.md)と[Production Brief](references/production-brief.md)。
3. 生成後: [Thumbnail QA](agents/thumbnail-qa.md)と[QAチェックリスト](references/qa-checklist.md)。
4. 判断境界の確認: [評価ケース](references/evaluation-cases.md)。

役割ファイルは独立したagentのインストールを要求しません。同じAIが順番に担当できます。役割ファイルの「共通ラスター生成入口」は、この公開版では利用者が選び、使用を許可した画像生成機能を指します。

## 1. イベントの価値を読み取る

既存資料から目的、開催する理由、仕事上の価値、対象者、確定コピー、掲載しない情報を抽出します。資料にある情報を再質問しません。方向性が大きく変わる情報だけ、必要なら確認します。

正式タイトルがある場合は保持し、改行や字間で表現します。別のコピーへの変更や短縮は、利用者から依頼された場合に限ります。タイトル未定ならコピー案を仮案と明示します。

## 2. 参照画像は任意

提示された場合だけ、配置・情報密度、文字表現、色、質感に分解します。採用点と非採用点を記録し、別々の画像の外観を無断で混ぜません。制作思想だけを参考にするのか、外観を参考にするのかも区別します。

元イベントの文字、日付、URL、ロゴ、固有モチーフを新しいイベントへコピーしません。お気に入り管理システムの導入は不要です。参照するファイルが読めない場合は、その参照を確認済みと扱わず、画像なしで続けるかを確認します。

## 3. Concept Gate: 画像を作らず方向性を比較する

通常3〜5案。目的が固まっていれば3案、探索が必要なら5案、方向性を指定済みならその1案を精緻化します。

発想レンズは、参加前後の変化、仕事の成果、なぜ今かという問い、仕事の流れ、コミュニティの思想から選びます。各案には以下を含めます。

- 短い名前とおすすめ順位
- メインコピー、小さく入れる確定情報
- 文字の意味を変形・接続・反復・余白などに翻訳する具体案
- 構図・配色・質感・情報密度
- 伝わる価値、向いている場面、トレードオフ、推薦理由

配色や背景だけを変えた案を並べません。「アート風」を黒板・チョークなど一つの質感に固定しません。周辺の装飾だけでなく、文字の意味が形へつながる箇所を説明します。

## 4. Selection Gate: 選択を制作指示へ固定する

利用者が選ぶまで画像生成へ進みません。「おすすめで作成」のような明示委任は選択として記録します。「AとBを作成」は両案への承認です。各案のBriefを作り、承認済み範囲を実行します。

選択案、選択元、伝達目的、exact text、文字表現、構図、配色、質感、除外事項をProduction Briefに記録します。複数案を混ぜる場合も一つの整合したBriefへ整理します。

## 5. Production Gate: 利用者の環境で画像化する

画像化の承認と生成機能の利用条件を確認し、利用可能な画像生成機能へBriefを渡します。別の有料サービスへ無断で切り替えません。機能がなければ生成用プロンプトを渡して終了できます。

既定は16:9の主版1枚。掲載先・利用者が比率を指定した場合はそれを優先します。生成指示には次を含めます。

- 確定した文字列と追加テキスト禁止
- 文字の意味を形へ変換する方法
- 主見出しと日時・場所・形式・主催名の情報階層
- 構図、比率、セーフマージン、縮小時の可読性
- 参照画像を使う場合の採用・非採用レイヤー
- 未承認のロゴ、URL、機能一覧、意味不明な英数字の禁止

## 6. QAと必要な派生版

実際の生成画像を見て、文字列、可読性、追加情報、方向性、実寸比率を確認します。希望サイズを実寸の証拠にしません。失敗した軸だけ修正し、無制限に再生成しません。

正方形版が必要なら主版のQA後に、同じBriefから1:1を別構成として作ります。中央トリミングだけで済ませません。

## 7. 成果物を渡す

利用者が指定した保存先に版付きファイル名で保存し、既存版を上書きしません。保存先が未指定なら確認するか、環境が返すダウンロード方法を案内します。公開操作は別の承認がない限り行いません。

画像に加え、[Production Brief](references/production-brief.md)の記録形式で選択・制作指示・生成状態・QAを残します。ローカルファイルを取得できる場合はSHA-256と実寸を検証します。取得できない値はnullと理由を記録し、整合性確認済みと報告しません。

役割ファイルにあるsidecarは、この公開版では上記の成果物記録を指します。生成サービス固有のsidecarがあれば併用できますが、作者のツールをインストールする必要はありません。
