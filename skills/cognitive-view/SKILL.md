# Cognitive View

長い資料を **同じ情報量のまま、すいすい読める解説記事へ** 変える。減らすのは「読みにくさ」であって、情報でも文章でもない。

目指す形は、経済メディアの解説記事のような **文章と図解の組み合わせ** である。ダッシュボードではない。読者は上から文章を読み進め、文章だけでは追いにくい所（数値の比較、推移、因果、立場の違い）で図表に目を移し、また文章へ戻る。文章は短い段落と文字組みで軽くし、図表は文章の主張を一目で確かめられる場所にだけ置く。

作るものは **受け取った本人が理解するための画面** である。提出物ではないので、見栄えより「速く正しく分かること」と「原文へ辿れること」を優先する。

## 最優先の約束: 原文にないものを足さない

このSkillの価値は、読み手が **画面を信じてよい** ことにある。見やすくても1つでも原文と違えば、読み手は元資料を開き直し、時間は減らない。だから次の7つは、どんな見せ方の工夫よりも優先する。

**しない（1つでも該当したら作り直す）:**

1. **計算しない。** 合計・差・倍率（「倍増」「半減」のような言い方も含む）・年額換算・1人あたり・％への換算、前月比や「約2ポイント」のような差、「4か月かかった」のような期間の長さも計算にあたる。しない（原文に計算結果が書いてあれば、その値だけ使う）。「9割」は「9割」のまま書く
2. **単位を変えない。** 「月額」「1ユーザーあたり」「年間およそ」などの単位と条件を必ず数値と一緒に書く。単位の違う値を同じ列・同じ軸に並べない
3. **書かれていない担当・期限・日付・年号を付けない。** 「未定」と書かれていれば「未定」と書く。原文に年が無ければ年を付けない
4. **書かれていない因果・循環・順序を作らない。** 原文が理由を2つ並べていたら、2つ並べて描く（1本の連鎖にしない）。「循環」「悪循環」「本質的課題」は原文にその語か同じ意味の記述がある時だけ
5. **推奨・優先順位・評価語を足さない。** 「最安」「有力」「失敗」「成功」などの判定は、原文が言っている時だけ、言っている範囲で使う
6. **地の文で推測しない。** 記事の本文でも、書き手として「〜と考えられる」「〜の可能性がある」「〜が原因だろう」「〜を招いている」と書かない。推測や解釈は、原文の誰かが言っている時だけ、その人の言葉として書く。原文に無い機能・特徴も書かない
7. **発言者を消さない。** 意見・主張は「誰が言ったか」と一緒に書く。「未確認」「口頭のみ」などの根拠の強さも一緒に書く

判断材料（比較・推奨）が欲しいとユーザーが明示した時だけ、末尾に「判断材料」ブロックを1つ足してよい。その場合も、原文にないスコア・確度・金額は作らない。

## 手順（この順で。飛ばさない）

### 1. 事実台帳を作る（HTMLを書く前）

原文を頭から読み、**事実を1件ずつ** 番号付きで抜き出す。

```text
F1 | 数値 | {{何が}}は{{値と単位}} | 「{{原文そのまま}}」
F2 | 主張({{誰}}) | {{誰}}は{{何}}と考えている | 「{{原文そのまま}}」
F3 | 未確認 | {{何}}はまだ確認されていない | 「{{原文そのまま}}」
```

- 1行 = `番号 | 種類 | 内容（短く言い換えてよい） | 原文からのそのままの引用（20〜40字）`
- 種類: `数値` `事実` `主張(誰)` `経緯(いつ)` `比較` `未確認` `未決` `対立`
- 引用は **原文をそのまま写す**。言い換えた文を引用欄に入れない
- 原文の文をすべてどれかの番号でカバーする。1文に2つの事実があれば2行に分ける
- 台帳にない内容は、以後どこにも書かない
- リードや要点のように **複数の事実をまとめた文は書いてよい。** その文が使った台帳番号をすべて `data-f` に付ける。まとめのための台帳行を新しく作らない。まとめの文に、どの事実にも無い主張を入れない

台帳は出力HTMLの最後に「原文との対応」として `<details>` で残す（部品集の `LEDGER`）。

### 2. 関係を見つけ、表現を選ぶ

台帳の番号を塊に分け、塊ごとに **上から順に最初に当てはまった表現** を使う。

| 優先 | 塊が持つ関係 | 表現 | 部品 |
|---|---|---|---|
| 1 | **同じ単位の数値が3つ以上**（または表の1列に2つ以上）、大小・推移・内訳が論点 | 棒グラフ（2時点なら棒＋◆）/ 折れ線（時点が書かれた出来事を重ねてよい）/ 表の中の小さな棒 | `BAR` `LINE` `SPARK` |
| 2 | **日付・月などの時点が3つ以上**（推移の折れ線に重ねられない出来事） | タイムライン図（順に現れるアニメーション可） | `TIMELINE` |
| 3 | **2つ以上の対象 × 2つ以上の観点** | 比較表 | `TABLE` |
| 4 | **原文が書いている** 因果・手順が3段以上 | 流れ図（原文の分岐・合流・対策をそのまま） | `FLOW` |
| 4b | **原文が書いている**「〜が確かめられないと〜が決まらない」 | 依存図（未確定の前提 → 待っている判断） | `DEPEND` |
| 5 | 同じ論点で立場が割れている | 対立ブロック（左右に並べる） | `CONFLICT` |
| 6 | 未確認・未決・宿題 | 未解決ブロック（状態記号つき） | `OPEN` |
| 7 | 並列の項目 | 箇条書き | — |
| 8 | 単独の事実 | 1文 | — |

- 上の条件を満たす塊は図表にする。**ただし図表は本文の代わりではない。** 図表を置いた章にも、図表が何を言っているかを本文で1〜2文書く
- 条件の7（並列の項目）と8（単独の事実）は、原則として **本文の段落** で書く。箇条書きやカードに刻まない
- 図表は1章に1つまでを目安にする。全章を図表で埋めない
- 1つの塊に1つの表現。同じ事実を2つの図に重ねて描かない
- 図の線と色は、部品集の「線と色の約束」に揃える（実線 = 原文の事実、破線 = 未確認・速報・予定）
- 図表が2つ以上続いたら、間に本文を挟むか、`BIG`（数値か引用を1つだけ大きく）で息継ぎを入れる
- 数値の塊は、同じ単位のものだけで1つのグラフにする。単位が違うなら別々にする

### 3. 記事として組む

| 部分 | 中身 |
|---|---|
| **冒頭**（5秒で掴む） | 小さなラベル（資料の種類） → `h1` =「主題 — 現在の状態」 → リード文（3〜4文。何が起きていて、何が決まっていないか） → 「この記事の要点」3つ（各1文、`POINTS`） |
| **本文**（章ごと） | 結論型の小見出し（`h2`。問いか、答えの1文） → 本文の段落 → 必要な時だけ図表（`FIG` で包む）→ 図表の読み方を1文 |
| **末尾** | 未解決の論点（`OPEN`）→ 原文との対応（事実台帳、`<details>` で閉じる） |

本文の書き方:

- **原文の情報は、基本的に本文の文章で運ぶ。** 図表に載せた事実も、本文で要点を1文は書く。本文だけを読んでも筋が追えること
- 各章に段落を **2〜4つ**。1段落は **1つの論点・2〜4文・120〜200字**。長い段落を作らない
- 1段落に **太字は1か所まで**（その段落の結論の句）。マーカー（`mark`）は **1章に1か所まで**（読み飛ばしてもここだけは読んでほしい1文）
- 数値は太字（`b.n`）にし、単位と条件を一緒に書く
- 発言や立場は、本文で「誰が」を書いたうえで、原文の言葉を引用ブロック（`QUOTE`）か対立ブロック（`CONFLICT`）で示す
- 補足・注意・根拠の弱さは、本文を止めずに注記（`NOTE`）へ出す
- 見出しは原文の章立てを写さない。読者の問い（例:「何が決まっていないのか」）か、その答えの1文にする

全体の決まり:

- **台帳の事実の9割以上を、本文・図表・冒頭のどこかに出す。** 詳細層だけに押し込まない
- 原文をまるごと詳細層に貼らない。台帳の引用が裏付けになる
- 段落・図表・引用などの要素に、根拠の台帳番号を `data-f="F3 F7"` で付ける

### 4. HTMLを書く

`references/components.md` の部品を組み合わせる。部品の `{{…}}` を台帳の内容で埋め、部品にない装飾を足さない。部品は **形だけの見本** で、書かれた例の言葉を中身に使わない。

- 単一のHTMLファイル。`<script>`、外部CSS・フォント・画像・CDNは使わない
- 日本語はSVGの中でも `<text>` で書く
- 幅320pxでも横にはみ出さない（比較表は狭い画面で行ごとのカードに変わる）
- 印刷で詳細層が消えない

### 5. 見直す（出力する前に）

次の6点を自分で確認し、ダメなら直してから出す。確認結果は出力に書かない。

1. 画面上のすべての数値（カード・グラフ・表）が、原文と **同じ表記** で台帳に載っているか。「割」を「%」に、内訳を合計に、2つの値を差にしていないか
2. 担当・日付・年号・因果・評価語・機能や特徴・書き手の推測（「考えられる」「可能性がある」）で、台帳に無いものが無いか。担当欄は、原文が主語を書いたもの以外「記載なし」になっているか
3. 台帳の引用が、原文にそのまま存在するか
4. `h1` が「主題 — 状態」になっているか
5. 各章に本文の段落があるか（図表だけの章が無いか）。各図は、ラベルを隠しても線・位置・大きさで関係が読めるか。破線を使った図に凡例があるか。手順2で図表が当てはまる塊を、箇条書きにしていないか
6. アニメーションは部品の `ANIMATION` の決まりどおりか（1回だけ・動きを減らす設定で止まる）

## 返信の形

次のどちらか1つ。

- **チャット**: HTMLを **1つのコードブロックで最後まで** 出す。途中で説明を挟まない。前後の説明は2行以内
- **ファイルを書ける環境**（Claude Code / Codex など）: `.html` として保存し、その場所を1行で伝える。HTML本体は返信に貼らない

どちらでも、事実台帳・採点表・作業メモは返信本文に書かない（台帳はHTMLの中にある）。

## ファイル

- `SKILL.md` — この手順（これだけでも実行できる）
- `references/components.md` — HTMLの部品集（記事の骨格と文字組み、要点、引用、注記、数値カード、表、グラフ、タイムライン、流れ図、対立、未解決、事実台帳、アニメーション）。**HTMLを書く前に必ず読む**
- `scripts/check-output.mjs` — 出力HTMLを原文と照合するスクリプト（数値・引用・禁止要素）。実行できる環境なら出力後に回す

チャットAIに渡す時は、`SKILL.md` と `references/components.md` の2つ、そして資料を渡せば足りる。
