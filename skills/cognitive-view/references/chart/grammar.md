## なぜ Diagram と分けるか

`references/diagram/grammar.md` のゲートは **Diagram 用に較正されている**。そこにある **3文テスト**（散文で2文で書けるなら図にしない）は「**描写しにくい構造だから図にする**」という発想で、関係図には正しい。

しかしチャートの価値は描写しにくさではなく、**数値の読み取り速度**である。

> 「アルファは2,400円、ブリッジは1,100円、コンパスは原文に記述なし」

これは **1文** で書ける。3文テストを掛ければ必ず落ちる。**チャートは原理的にあのゲートを通れない。** 実測で、量の候補が `prose_sentences: 2` により却下され、桁が3つ違う金額が表のセルに同じ文字サイズで並ぶ出力が出荷された。

そこで本ファイルは、チャートに**別のゲートと別の複雑度予算**を与える。

**チャートに 3文テストと node/edge 予算を適用しない。** 適用するのは下の数値テストと §3 の予算である。

## 1. 数値テスト（チャートのゲート）

次の (a)(b)(c) を**すべて**満たす時、チャートにする。

| | 条件 |
|---|---|
| **(a) 量** | 原文に**同じ単位の値が3つ以上**ある（欠測を「記述なし」として数に含めてよい） |
| **(b) 差** | 値の間に**桁またはスケールの差**があるか、**推移・構成比・幅**のいずれかが論点になっている |
| **(c) 帰結** | その大小・推移・構成が、読者の理解（comprehension_goal）に効く |

3つのうち1つでも欠けるなら、数値は**表のセルか文**に置く。

**値が2つなら1文にする**（「A は B の 2.2 倍」）。ただし**その2値が表の列として並ぶなら §2 の sparkbar を使う**。

**原文にない値を作らない。** 合計・平均・比率・年額換算は、**原文にその計算結果が書かれている時だけ**描いてよい。書かれていない計算は `UNDERSTAND` の境界を越える。

## 2. 関係 → 型

| 数値が持つ関係 | 型 | ファイル |
|---|---|---|
| **表の1列に並ぶ値の大小** | Sparkbar（セル内インラインバー） | `type-sparkbar.md` |
| 3つ以上の独立した値の大小 | Bar | `references/diagram/type-bar.md` |
| 時間に沿った推移 | Line | `type-line.md` |
| 全体に対する内訳・構成比 | Part（積み上げ / ドーナツ） | `type-part.md` |
| 値に幅がある・確定していない | Range | `type-range.md` |

**表とチャートは競合しない。** 比較表の数値列には sparkbar を重ねる。`SKILL.md` の「表の後にさらに図を足す必要は普通ない」は**独立したチャートを足すな**という意味であり、セル内の sparkbar には適用しない。

型が決まらない、または2つの型にまたがるなら、**チャートにしない**。

## 3. 複雑度予算（チャート用）

Diagram の `node ≤9 / edge ≤12` は**適用しない**。チャートには次を使う。

- **系列 ≤ 3**（1枚に重ねる線・積み上げの分類数）
- **カテゴリ ≤ 8**（棒・スパークバーの本数。超えたら横棒にするか2枚に分ける）
- **focal accent ≤ 1**（Diagram の2より厳しい。チャートは既に位置でエンコードしているため、色の強調は1本で足りる）
- **凡例は使ってよい。** Diagram の「凡例なしで読める」は適用しない。ただし系列が2つ以下なら、凡例ではなく**線や棒の直上にラベルを置く**

## 4. 共通の描画規則

- **軸は必ず 0 から始める。** 途中から始めると大小の差が歪む
- **値ラベルを直接置く。** 読者に軸を読ませない
- 単位が違う値を1枚に混ぜない（金額と人数を同じ軸に置かない）
- グリッド線は極薄（`rgba(45,49,66,0.08)`）で3〜5本。ベースラインだけ濃く
- 日本語は `<text>` で描く（`<path>` でのストローク描画は禁止）
- 色トークンは `references/diagram/grammar.md` の Token 表を共有する

## 5. 不確認・欠測の描き方

**このSkillでは「原文に記述なし」を空白で飛ばさない。** 飛ばすと読者は「調べ忘れ」か「本当に無い」かを判別できない。

- **欠測**: その位置に**破線の空スロット**を置き、ラベルに「原文に記述なし」と書く。0として描かない
- **未確認の値**: 実線ではなく**破線枠**にし、ラベルに「未確認」と添える
- **幅のある値**: `type-range.md` を使う。点で描いて幅を消さない

**0 と「記述なし」を同じ見た目にしない。** これはこのSkillで最も起きやすい情報の欠落である。
