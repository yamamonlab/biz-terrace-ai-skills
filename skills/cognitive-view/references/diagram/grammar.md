# Diagram Grammar

Visual Router が図を選んだ塊を描くための文法。**この Skill は同じ環境に `diagram-design` があっても、常にこの `references/diagram/` を使う。** 参照先が2つあると、どちらの規則で描いたか後から判別できなくなる。

## 1. 関係 → 型

| 塊が持つ関係 | 型 | ファイル |
|---|---|---|
| 依存・因果（連鎖・循環・分岐） | 流れ図 | `type-flowchart.md` |
| 時系列（**時点4つ以上**、または経過期間が論点） | Timeline | `type-timeline.md` |
| 複数主体が順に引き継ぐ手順 | Process | `type-process.md` |
| 状態と遷移（イベントで移る） | State | `type-state.md` |
| 2軸上の位置づけ | Quadrant | `type-quadrant.md` |
| 親子の階層・分解 | Tree | `type-tree.md` |
| 3つ以上の値の大小 | Bar | `type-bar.md` |

型が決まらない、または2つの型にまたがるなら、**図にしない**。表か箇条書きへ落とす。またがる図は両方の読み方を要求するので、散文より遅くなる。

## 2. 複雑度予算

図1枚あたり:

- **node ≤ 9**（矩形・円・セル・棒などの意味を持つ要素）
- **edge ≤ 12**（矢印・接続線）
- **focal accent ≤ 2**（強調色を当てる要素）
- **凡例なしで読める**（凡例が要る図は、ラベルが足りていない）
- **3文テスト** — その図の内容を散文で書くと3文以上かかるか。2文で足りるなら図を作らない。

**チャート（棒・線・構成比・幅）にはこの予算と3文テストを適用しない。** 別のゲートと予算を `references/chart/grammar.md` が持つ。**この3つの数字の根拠と、動かしてよい条件は `references/foundations.md` の3節。** 超えたら、分割するか表・箇条書きへ落とす。**予算は図にだけ掛ける。** 表・箇条書き・カードは読解コストが低く場所も食わないので、関係があれば原則そちらへ寄せる。

## 3. Token

CSS 変数を使わず、literal hex で描く。単体で開いても色が落ちない。

| 役割 | 値 | 用途 |
|---|---|---|
| `paper` | `#f5f5f5` | 背景、既定の node 塗り |
| `ink` | `#2d3142` | 主要テキスト、主要ストローク |
| `muted` | `#4f5d75` | 副次テキスト、既定の矢印 |
| `soft` | `#5f6b80` | サブラベル、境界ラベル。`paper` / 白背景に対して 5:1 前後 |
| `rule` | `rgba(45,49,66,0.12)` | ヘアライン |
| `accent` | `#eb6c36` | focal。図1枚で1〜2要素まで |
| `accent-tint` | `rgba(235,108,54,0.08)` | accent 枠の塗り |
| `unknown` | `#8a2f2f` | 未確認・破綻点（cognitive-view 固有。破線と併用する） |

cognitive-view の出力 HTML へ埋め込む時だけ、`ink`→`var(--text-primary)`、`muted`→`var(--text-secondary)`、`unknown`→`var(--danger)` へ置き換えてよい（`references/output-contract.md` の CSS が定義している）。置き換えるなら図の中で統一する。

**accent を3要素以上に当てない。** 全部が重要だと、どれも重要でなくなる。

## 4. 線と形

| Token | 値 | 用途 |
|---|---|---|
| `stroke-thin` | `0.8` | 葉ノード、補助線 |
| `stroke-default` | `1` | ほとんどのストローク |
| `stroke-strong` | `1.2` | 強調 |
| `radius-md` | `6` | node 矩形 |
| `radius-lg` | `8` | コンテナ |
| grid | `4` | 座標・サイズ・間隔はすべて 4 の倍数 |

**形が種別を持つ。色ではない。** 角丸矩形＝ステップ、菱形＝分岐、楕円＝始点/終点、塗り円＝合流点。色で種別を示すと、色覚と印刷で情報が消える。

破線（`stroke-dasharray="5 4"`）は未確定・任意・想定を表す。実線と混ぜる時、何が破線なのかを必ずラベルで書く。

## 5. 文字

- 日本語は必ず `<text>` で書く。`<path>` でのストローク描画は禁止（コピー・検索・読み上げが壊れる）。
- `font-family="sans-serif"` を既定にする。外部フォントを読み込まない。
- node 名 12〜13px、サブラベル 10〜11px、軸ラベル 10px。
- 文字が図からはみ出すなら、ラベルを短くするのではなく **node を減らす**。
- **日付ラベル・サブラベル・注釈は本文と同じ判別可能性を持たせる。** 小さい文字ほど薄くしたくなるが、11px の文字こそ背景とのコントラスト比 **4.5:1 以上**（WCAG AA 相当）が要る。`soft`（`#5f6b80`）より薄い灰色をサブラベルに使わない。図の中の文字は本文と違い拡大・選択で補えないので、薄さは情報の欠落になる。

## 6. 必須の属性

すべての `<svg>` に次を付ける。

```svg
<svg viewBox="0 0 W H" role="img" aria-label="この図が示すこと">
  <title>図タイトル</title>
  <desc>一文説明</desc>
</svg>
```

`width`/`height` 属性は付けず、`viewBox` と CSS の `width:100%;height:auto` で伸縮させる。320px 幅で横 overflow を出さないため。

## 7. Anti-pattern（全型共通）

1. **色で種別を示す** — 形・線種・ラベルで示す。色は focal だけ。
2. **凡例に頼る** — 凡例を読まないと意味が取れないなら、ラベルが足りない。
3. **全要素が同じ大きさ・同じ色** — 中心命題が見つからない。
4. **装飾のためのアイコン・影・グラデーション・3D** — 関係の理解を改善しないものは入れない。
5. **ラベルを隠すと何も読めない** — geometry だけで因果・時間・境界のどれかが読めること。
6. **異なる関係を同じ topology へ押し込む** — 比較の塊と因果の塊を同じ列グリッドで描かない。
7. **予算超過を縮小で解決する** — 文字を小さくして詰め込むのは、読めない図を作ること。
8. **1つの図に2つの主張** — 分割する。

## 8. 描く前の確認

1. この塊の関係は §1 の表で1つの型に決まったか。
2. 3文テストを通ったか。
3. node ≤9 / edge ≤12 / focal ≤2 に収まったか。
4. 凡例なしで読めるか。
5. 日本語は `<text>` か。
6. `role` / `title` / `desc` があるか。
7. 図はページ全体で3枚以下か。

1つでも NG なら、図をやめて表・箇条書きへ落とす。**図が描けないことは失敗ではない。背骨が図でない資料の方が多い。**
