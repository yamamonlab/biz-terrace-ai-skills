# Quality Rubric — Cognitive View 採点表

3つの主指標（情報保持率・表現変換率・視覚エンコーディング率）と、9軸 × 各 0-2 点（満点 18 点）。

**この表が採点の正本。** SKILL.md は即 FAIL と自己チェックだけを持ち、合格条件をここへ委ねている。

この採点は**成果物の性質**を測る。読者が実際に速く把握できたかは測っていないので、それは `references/eval-protocol.md` の理解到達テストで別に測る。両方を通った時だけ EVALUATED と記録する。

`DECIDE` モードでは、下の主指標・7軸・即 FAIL に加えて `references/decide-contract.md` の軸8と即 FAIL 2件を適用する。

**合格条件: 情報保持率 95% 以上 かつ 表現変換率 80% 以上 かつ 視覚エンコーディング率 30% 以上 かつ 9軸 15 点以上、かつ即 FAIL ゼロ。**

主指標を先に置くのは、このスキルの設計軸が「見せる量を減らす」ではなく「同じ量を、読まずに済む表現へ変換する」だから。9軸だけで採点すると、情報を削って見た目を整えた出力が高得点になる。

**主指標3（視覚エンコーディング率）を別に置くのは、表現変換率が「散文でない」しか測れないから。** 箇条書きは非散文だが位置や大小で情報をエンコードしないので、全部を箇条書きにしても表現変換率は 100% になる。実測でそれが起きた（構造層9ブロック中、図1枚・箇条書き5連続で合格）。配分の事前規定は `references/representation-budget.md`。

## 主指標1 — 情報保持率

> 原文の事実・数値・未確認事項のうち、出力のどこか（5秒層・構造層・詳細層のいずれか）に残っている割合。**目標 95% 以上。**

### 計測手順

1. **原文から原子項目を列挙する。** 1項目 = それ単独で真偽が言える最小単位。
   - 数値（金額・人数・期間・割合）は1つずつ独立した項目にする。
   - 「誰が何と言ったか」は、発言者と内容のセットで1項目。
   - 未確認事項は、その内容と「なぜ未確認か（根拠の弱さ）」を別項目にする。
   - 見出し・接続詞・文体は項目にしない。
2. 列挙した項目に通し番号を振り、表にする（この表が計測の証跡になる）。
3. 各項目について、出力に残っているかを ○ / × で判定する。
   - 表のセル、図の `<text>`、箇条書きの一項目、`<details>` の中——どこにあっても ○。
   - 言い換えられていても、同じ事実が読み取れれば ○。
   - 数値が丸められている、条件が落ちている場合は ×。
4. 情報保持率 = ○の数 ÷ 全項目数。× になった項目は、番号と内容を報告に残す。

**原子項目の列挙は1回作って両方の出力に使い回す。** 出力ごとに項目を切り直すと、比較が成立しない。

## 主指標2 — 表現変換率

> 関係を持つ塊のうち、散文以外（表・timeline・流れ図・箇条書き・カード）で表現された割合。**目標 80% 以上。**

### 計測手順

1. **出力を塊に切る。** 1塊 = 問い見出しまたは `<details>` の下にある1つの論点。
2. 各塊が **関係を持つか** を判定する。関係あり = 内部に2つ以上の項目があり、比較・時系列・依存因果・列挙のいずれかで結ばれている。
3. 次の塊は関係の有無にかかわらず **分母から除く**。
   - 他の文と関係を持たない単発の1文。
   - **Visual Router が散文を指定した塊** — 「依存・因果（2ステップ以内）→ 断定文1文」「比較（軸2つ以下）→ 1文」に該当するもの。ルーターに従った結果を変換漏れとして数えない。判定は塊内の項目数（因果なら2ステップ以内、比較なら軸2つ以下）で機械的に行い、報告には「Router 指定の散文」と1行残す。
   - 隣接する図・表で既に構造化済みの内容を、要約・接続するだけの1文。
4. 関係ありの塊を分母とする。`<details>` 内のブロックは次で振り分ける。
   - **分母から除く（＝原文引用）**: その内容が本文層（5秒層・構造層）に構造化された形ですでに現れており、`<details>` は原文の該当箇所を再掲しているだけの場合。引用は変換しないのが仕様。
   - **分母に入れる**: 本文層に無い情報を含む場合。畳んだだけで変換していないので、散文なら ✗ として数える。
   この振り分けが、「構造化できたものは畳まない」を機械的に測る箇所になる。
5. 各塊の表現を分類する。
   - **非散文**: `<table>` / `<svg>` の図 / `<ul>` `<ol>` / `.card`
   - **散文**: `<p>` の連続文、`<details> > div` 内の地の文
   - 表や図の直前に置く `.rel` 1行は導入であり、塊の表現とは数えない。
6. 表現変換率 = 非散文の塊数 ÷ 関係ありの塊数。散文のまま残った塊は、番号と「なぜ散文か」を報告に残す。

**`<details>` の中身も分母に入れる（原文引用を除く）。** 要約を散文のまま `<details>` へ押し込む形は、変換せずに畳んだだけであり、このスキルが避けたい状態そのもの。

## 主指標3 — 視覚エンコーディング率

> 関係を持つ塊のうち、**視覚エンコーディング装置**（メトリクスカード群 / 表 / 図 / アラート枠）で表現された割合。**目標 30% 以上。**

### 計測手順

1. 分母は主指標2と同じ「関係を持つ塊」。切り方も同じものを使い回す
2. 各塊の装置を分類する。**箇条書き・日付付きリストは視覚エンコーディングに数えない**（順序しかエンコードしていない）
3. 視覚エンコーディング率 = 視覚装置の塊数 ÷ 関係ありの塊数

**下限を満たすために装置を足してはいけない。** 数値のない資料にカードを作る、列挙を表に入れる、装飾の図を描く、はいずれも即 FAIL 2 に当たる。満たせない入力（関係を持つ塊が3件未満）では、その旨を報告に1行書いて下限を適用しない。規定は `references/representation-budget.md` の第2層。

## 9軸

| 軸 | 0 点 | 1 点 | 2 点 |
|---|---|---|---|
| **1. 5秒層** | 見出しだけでは何の資料か分からない、またはカードが5枚以上 | 何についてかは分かるが、要点が読み取れない | 見出し（主題＋状態）＋カード最大4枚（数値がなければ状態の短文）で全体像が立つ |
| **2. 構造層** | 論点が羅列されているだけで問いに答えていない | 問い見出しはあるが、塊と表現が対応していない | 問い見出しごとに塊が整理され、30〜90秒で構造を追える |
| **3. 詳細層** | 詳細が既定で開いている、または根拠に辿れない | 畳まれているが、変換できた塊まで畳んでいる | 原文引用と経緯の細部だけが畳まれ、本文セクションとの対応・原文位置が明確。全行リンクなしで辿れる |
| **4. 事実区別** | 推測・未確認が事実と混在して見分けられない | 区別はあるが色のみ、または表・カードの中で区分が落ちている | 見出し・状態列・注記・アラートで区別され、帰属と未確認が明確。全行バッジがなく色以外の手掛かりがある |
| **5. 図の妥当性** | 装飾目的の図がある、または3文未満で書ける内容を図にしている | 図はあるが複雑度予算超過、または凡例なしでは読めない | 条件を満たす図が主役で、3文テストと複雑度予算内。図が不適切なら理由付きで表・リストへ置換 |
| **6. 議事録性** | 見出し列が元資料の章順の写し | 見出しは問いの形だが、最大サイズ要素が2つ以上ある | 見出しが読者の問いへの答えで、最大サイズは見出し1つだけ |
| **7. 描画可否** | 外部読み込みか `<script>` があり `file://` で壊れる | 描画はするがレイアウト崩れ・overflow がある | 完全自己完結、320/768/1024 幅で overflow なし |
| **8. 視覚エンコーディング** | 構造層がテキストカードと箇条書きだけで、位置・大小で情報を示す装置が無い。または装飾目的の装置が混入している | 装置はあるが下限30%未満、もしくは1種類に偏っている | 下限を満たし、各装置が実際の関係をエンコードしている。水増しがない |
| **9. リズム** | 同一装置が3つ以上連続する。散文が3つ以上連続する | 同一装置の2連続が1か所ある | 同一装置の連続なし。5秒層と最初の問い見出しが1画面に入る |

採点手順（軸5）: 数値も関係もない資料に図やKPIを捏造していないことを先に確認する。図が不要と判断した場合はVisual Routerとの一致で採点する。 図ごとに、その図の内容を散文で書き下して文数を数える。3文未満で書けるなら 1 点以下。timeline は「時系列だから」を根拠にせず、時点の間隔・並行・逆順・分岐が意味を持つかで判定する。次に node / edge / accent を数える。

採点手順（軸8）: まず `references/representation-budget.md` の予算表があるかを見る。無ければ 1 点以下（事後の自己申告になるため）。次に視覚装置の塊数を数え、下限30%と突き合わせる。最後に各装置が**実データをエンコードしているか**を見る。数値のないカード、比較でない表、3文テストを通っていない図は、あっても加点しない。

採点手順（軸9）: 出力を上から読み、装置の並びだけを書き出す（例: カード群 → リスト → 表 → リスト → 図 → 散文 → アラート → リスト → リスト）。同一装置が隣り合う箇所を数える。次に 1024px 幅で描画し、5秒層と最初の `<h2>` の先頭が 900px 以内に入るかを見る。

採点手順（軸6）: 見出しだけを縦に読み、元資料の章名（経緯・比較・未確認・宿題など）と一致する語が過半なら 0 点。次に `font-size` を確認し、`h1` と同等以上のサイズを持つ要素が他にあれば 1 点以下。**ブロック数の多さは減点理由にしない**（情報を保つ設計のため）。

## 即 FAIL（点数に関わらず出荷不可）

1. 外部読み込みまたは `<script>` がある
2. 原文にない事実を追加している、または要約で意味が反転している
3. `UNDERSTAND` モードなのに推奨・優先順位を提示している
4. 機密情報・個人情報がそのまま埋め込まれている
5. CJK が SVG `<path>` でストローク描画されている
6. 情報保持率が 90% を下回っている（変換ではなく削減になっている）
7. 関係を持つ塊が3つ以上あるのに、視覚エンコーディング装置が1つも無い（箱組みへの退行）
8. 図を出しているのに、`references/representation-budget.md` の事前散文（`prose` / `prose_sentences`）が記録されていない
