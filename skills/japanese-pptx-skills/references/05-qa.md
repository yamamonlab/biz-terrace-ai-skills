# 工程5｜計測で検証

## Principle
QAを「感想レビュー」にしない。LLM検査と機械検査を分離し、問題をコード化する。

`DESIGN.md` 適合も「好み」ではなく、意味・比較・視線・geometryの検査として扱う。

## Severity
- BLOCKER: 完成扱い不可。事実誤認、論証破綻、捏造、数値矛盾、意味を歪める比較等。
- ERROR: 完成扱い不可。形式・追跡・描画・出典・design contractの明確な違反。
- WARN: 改善推奨。意思決定を妨げない軽微な問題。

## LLM checks
### Evidence integrity
- 仮説を事実扱いしていないか。
- 断定強度は根拠強度と一致するか。
- 外部調査の主要主張が弱い事例ソースだけに依存していないか。
- ベンダー事例を一般化していないか。

### Head message
- 完全文か。
- 判断語があるか。
- 図表の読み上げに留まっていないか。
- 逆テストを通るか。
- cover / dividerを除き1ページ1メッセージか。

### Storyline
- head縦読みで結論と論点を再構成できるか。
- 前後が therefore / because / however / parallel で説明可能か。
- 同階層のslice_axisが1つか。
- Briefing templateを使っている場合、11枠を埋めることが目的化していないか。

### Proof mapping
- head各節をどの本体要素が証明するか指させるか。
- Evidence → proof requirement → body elementが切れていないか。
- 図内 `local_judgment` が新規主張を追加していないか。

### Visual fit
- selected_patternが最短視線で主張を証明するか。
- pattern invariantsを守っているか。
- キー値・終点・乖離・閾値が必要な箇所で直接示されているか。
- 実績と予測が視覚的に区別されているか。

### Design System
`DESIGN.md` に基づき確認する。
- analysis pageでheadが視覚上の主役になっているか。
- proof要素と対応する主張節の位置関係が追いやすいか。
- 比較対象が共通スケール・単位・期間で比較されているか。
- 強調が1〜2箇所に絞られているか。
- 意味のない影、gradient、カードUI、アイコンが増えていないか。
- page roleに合ったdensityか。
- 主要差分・閾値・現在地が凡例探索を要求していないか。
- 色だけでactual/forecast、risk、selection等を区別していないか。
- 同roleページのhead/body/footer geometryが不必要に揺れていないか。
- 5秒scanで「主張 / 根拠 / 視線先 / 決定」が把握できるか。

### Decision closure
- SummaryのDecision IDがClosingで回収されているか。
- Closingに決定事項・日程・判断基準があるか。
- 調査ブリーフィングが外部環境の説明だけで終わらず、自社の意思決定へ接続しているか。

## Machine checks
### IDs and traceability
- Evidence ID / Slide ID / Decision IDの参照整合性
- proof_requirements → body_elementsの参照整合性
- data_bindings → Evidenceの参照整合性
- emphasis_targets → body element / callout IDの参照整合性（指定時）

### Numeric integrity
- 実質数値の出所または試算前提
- 推計値に `is_estimate=true` と推計方法/前提
- 推計Evidenceを使うページに `estimate_disclaimer=true`
- ブリッジ図：`start + sum(contributions) = end` がtolerance内で一致
- 同じ指標を表示する表とグラフが共通Evidence / data bindingを参照

### Forecast integrity
- `forecast_present=true` のとき `forecast_encoding` がある
- 実績と予測の視覚区別が定義されている
- 予測境界labelがある
- deck-level semantic encodingでactualとforecastが同じ場合は、slide design contractにsemantic redundancyがある

### Design contract integrity
v1.2かつ `VISUAL_READY` 以降：
- `deck.design.system` がある
- 各slideに `render.design_contract` がある
- `density` が analytical / breathing のいずれか
- analytical pageは原則 `primary_focus=head`
- cover/dividerは原則 breathing
- emphasis_targetsが3個以上ならWARN
- `geometry_key` が空ならWARN
- design exceptionにはscope/rule/reasonがある
- v1.2では `brand.theme_profile` ではなく `design.theme_profile` を正本にする

### Source footer
外部調査Evidenceを使う分析ページでは、source noteがそのEvidenceを参照しているか。
推計値がある場合、`†：推計値を含む` が表示仕様に含まれるか。

### Head / render
- headの禁止語・禁止記号
- head内数字数
- 文字幅/行数の目安
- slide bounds外
- bbox overflow
- 重大な図形重なり
- 共通軸/位置の機械的整列（取得可能な場合）
