# 工程1｜言い切る（ヘッドメッセージ）

## Goal
図を作る前に、各ページが何を判断させるかを一文で確定する。

## Writing sequence
1. このページは何の問いに答えるか。
2. 答え（判断）を一言で置く。
3. 支えるEvidenceを1つ以上選ぶ。
4. 判断と根拠を接続語で1文にする。
5. まず1行相当を狙い、入らない場合のみ2行にする。

## Rules
- 主語と述語のある完全な文。
- 1ページ1メッセージ。
- 事実＋判断を1文に持つ。
- 目安30〜60字。まず36字幅相当の1行。必要時のみ56字幅相当までの2行。
- 改行は文節で行う。
- 判断語と接続語を優先して残し、削るなら根拠節から削る。
- 実質数値は1文最大2つ。
- 隣接3枚で同型を続けない。

## Useful judgment forms
- 〜すべきだ
- 〜に限られる
- 〜に値する
- 〜を左右しない
- 〜ではなく〜だ
- 〜にすぎず
- 〜が見込める
- 〜できる
- 〜が必要だ

## Sentence patterns
- causal: 〜のため、〜する
- conditional: 〜すれば、〜が固まる
- contrast: 〜だが、問題は〜にある
- origin: 〜を左右するのは〜ではなく〜だ
- evaluation: 〜は〜の範囲にあり、〜を左右しない
- proposal: 〜に、〜を集中させるべきだ

## Prohibited
- 「〜の分析」「〜について」など題名だけの文
- `A。B` の二段構え
- 「課題は3つ」など要素個数そのものを主張にする
- 体言止め
- ダッシュ `——`
- 「本ページ」「この1枚」等の自己言及
- So What 帯への示唆の退避

## Claim strength
根拠の強さと断定の強さを一致させる。

- strong: 十分な確定根拠 → 「〜すべきだ」「〜である」
- moderate: 定量根拠はあるが不確実 → 「〜が妥当だ」「〜が見込める」
- hypothesis: 仮説段階 → 「〜を第一仮説として検証すべきだ」
- insufficient: 根拠不足 → 「判断にはxxの確認が必要だ」

## Reverse test
本体だけを見た人が同じ文をそのまま書けるなら、判断が足りない。図表内容の読み上げではなく、経営判断を加える。

## Proof mapping
ヘッドを意味の節に分け、各節に `proof_requirements` を作る。各節はEvidence IDを1つ以上参照する。

## Decision box
決定を求めるページだけ、下部に1行の論点ボックスを置いてよい。表記は `〜の可否` 等。通常ページには置かない。

## Gate 1
BLOCKER:
- ヘッドがEvidenceで支えられない
- 根拠不足なのに強い断定をしている

ERROR:
- 完全文でない
- 判断語がない
- 1ページに独立した主張が2つ以上ある
- 禁止表現に該当
- 実質数値が3つ以上

WARN:
- 30〜60字から大きく外れる
- 1行想定を十分検討せず2行にしている
- 隣接ページと文型が単調

Gate 1通過後：`MESSAGE_READY`
