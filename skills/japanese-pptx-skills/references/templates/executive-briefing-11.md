# Template｜Executive Briefing 11

## Positioning
経営層向けに外部テーマを短時間で理解し、「自社として何を決めるか」まで接続するための標準11枚テンプレート。

**これはページ固定ルールではない。** Message / Storyline を先に作り、ストーリーが合う場合だけ適用する。Evidenceが弱いページは削除・統合し、意思決定に必要なら別ページを追加する。

## Use when
- テーマ起点の調査ブリーフィング
- 読み手が経営層
- 9〜12枚程度
- 外部環境 → 自社への含意 → 行動まで一巡させたい

## Default sequence

### P1 Cover
目的：テーマと資料の問いを一目で示す。
- analytical head は不要な構造例外
- モチーフはテーマの核心を示すもの1つ
- アニメーションは出力仕様が許す場合のみオプション

### P2 Executive Summary
目的：資料全体の結論・主要KPI・論点・求める決定を先に示す。
- headは1つ
- 補助要素として長期トレンド、KPI 2〜3点、用語/口径、Decision ID一覧を配置可能
- 3つの「エグゼクティブポイント」を置く場合も、headと矛盾する独立メッセージにしない
- 候補 intent: decide / timeline
- 候補型: 02, 05, 31, 33

### P3 Definition / Landscape
目的：何を対象に議論しているか、成熟段階・分類・全体像を固定する。
- 定義、進化ステージ、分類、対象範囲
- 候補 intent: structure / relationship
- 候補型: 41, 44, 46, 32

### P4 Adoption / Diffusion
目的：普及のどこに「溝」があるかを特定する。
- 認知→検討→試行→展開等は素材/調査に実在する段階のみ使う
- 部門差・段階別障壁・典型失敗を併置してよい
- 候補 intent: decompose / compare
- 候補型: 08, 07, 14, 15

### P5 Impact
目的：何がどこへ移り、どのKPIにどの程度効くかを示す。
- 人時、コスト、売上、リードタイム等の移動を定量化
- 実績事例は確認レベルを明示
- 候補 intent: decompose / structure / relationship
- 候補型: 09, 10, 12, 23, 40, 48

### P6 Use-case / Priority Map
目的：どこに経営資源を寄せるべきか決める。
- 軸は「決定に効く2軸」を使う
- 閾値は図上に直書き
- ROIは出所/試算前提を保持
- 候補 intent: decide / relationship / compare
- 候補型: 06, 19, 32, 23

### P7 Barriers / Responses
目的：導入を阻害する要因と、解消の優先順位を示す。
- 障壁上位、対策、リスクKPI、対応順序を対応付ける
- 候補 intent: compare / decompose
- 候補型: 14, 45, 46, 11

### P8 Operating Model
目的：人・システム・会議体の役割と、例外処理を示す。
- 人の判断点、差戻し、責任分担、エスカレーション基準
- 候補 intent: timeline / structure
- 候補型: 47, 38, 39, 48

### P9 External Comparison
目的：国・業界・企業規模など同じ物差しで差を示し、自社の追い上げ余地を定量化する。
- 乖離は図上に `○○pt` 等で直書き
- 候補 intent: compare
- 候補型: 14, 16, 19, 28

### P10 Regulation / Governance / Ecosystem
目的：外部制約とプレイヤー動向が、自社の判断にどう効くか示す。
- 規制時系列、チェック事項、プレイヤー被覆を必要に応じて選ぶ
- 候補 intent: timeline / structure
- 候補型: 31, 35, 41, 42, 48

### P11 Roadmap / Decision Closure
目的：現状から目標への移行を、責任・指標・期限・主要リスクまで含めて決める。
- SummaryのDecision IDを同じ番号で回収
- 起点→寄与→終点を使う場合は必ず検算
- 即日開始アクションは、決定済みまたは明確な提言としてEvidenceと区別
- 候補 intent: decide / timeline / decompose
- 候補型: 03, 07, 35, 36, 37

## Compression rule
10分報告や9枚程度に圧縮する場合の候補：
- P3 DefinitionをP2へ統合
- P10 RegulationをP9またはP11へ統合

ただし削除は時間都合ではなく、Decisionに必要な証拠が残ることを確認して行う。

## Expansion rule
11枚を超える場合は、同種対象の個票、事例深掘り、補足データを追加してよい。論点を増やすために枚数を増やさない。

## Template QA
- 11枠を埋めること自体を目的にしていないか
- P2とP11で同じDecision IDを予告・回収しているか
- 外部環境説明が自社の判断に接続しているか
- ページごとの型が固定指定ではなく、Messageに合わせて選ばれているか
