# Eval Protocol — Skill を変えた時の測り方

実行時には読まない。Skill の振る舞いを変える時に使う。

## 1. VALIDATED と EVALUATED

| 状態 | 満たしているもの |
|---|---|
| **VALIDATED** | `scripts/validate.mjs` が PASS。Skill のファイル同士が矛盾していないことだけを確認した状態 |
| **EVALUATED** | 下の2〜4を、**2つ以上の入力** × **3段階以上の強さのモデル** で実施し、合格条件を満たした状態 |

`CHANGELOG.md` には、どちらであるかを必ず書く。手順・表現の振り分け・台帳・層の規則を変える時は EVALUATED まで行う。

## 2. 事前登録（生成より先に書いてファイルに残す）

- 条件（Skill の版、読み込み経路、モデル、回数）
- 合格基準
- 原文の事実リストと、捏造として検出するパターン
- 理解の設問（5節）

**出力を見てから基準や設問を作らない。** 2026-09-22 の初回テストはこれを破り、天井効果になった。

## 3. 生成の条件

- 参加者と同じ経路を再現する。チャット経路は `SKILL.md` + `references/components.md` + 資料だけを渡す。フォルダ経路はフォルダ全体を渡す
- 1回きりの生成（描画・検証・作り直しをさせない）
- 弱いモデルを必ず含める。**崩れるのは弱いモデル**で、強いモデルだけで測ると合格してしまう

## 4. 忠実さの判定（最優先）

各出力に `scripts/check-output.mjs <output.html> <source>` を回し、加えて構造層（`<details>` の外）を人が読む。

| 判定 | 基準 |
|---|---|
| 捏造 | 原文に無い数値・計算・年号・担当・因果・評価語。単位の変更。スクリプトの ERROR は全件、WARN は人が確認 |
| 台帳 | 引用が原文にそのまま存在する |
| 保持 | 事実リストの9割以上が構造層に出ている |

**合格条件: 全出力で捏造0。** 1本でも出たら、どの規則が弱いモデルに届いていないかを特定して直す。

## 5. 理解の判定

独立した読者（出力の生成に関わっていないモデルか人）に、5秒層だけ → 構造層まで、の2段階で答えさせる。

- 設問は4問。うち1問は必ず **事実と推測の区別**、1問は **5秒層だけでは答えられないはずの弁別設問**
- 正答率に加えて **探索コスト**（ツール使用回数・所要時間・拡大回数）を記録する。正答率は天井に張り付きやすい
- 誤答は「情報が無い」と「情報はあるが読み取れない」に分ける

## 6. 記録

`実施日 / Skill の commit / 入力 / 条件表 / 判定表 / 見つかった捏造の全文 / 検証できなかったこと` を残す。モデル名は、参加者が使う実際のAIの **代わり** であることを明記する。
